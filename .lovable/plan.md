## План внедрения AEO/GEO-улучшений TokenBel

Три независимых блока, можно катать по одному. Все правки — только в статических HTML/JSON, никакого бэкенда.

---

### Блок 1. Robots.txt — явные правила для AI-search ботов

**Файл:** `public/robots.txt` (сейчас: 3 строки, `User-agent: *  Allow: /` + Sitemap).

**Что делаем:**
1. Оставляем текущий `Allow: /` для всех как fallback.
2. Добавляем явные блоки `Allow: /` для search-индексеров, которые цитируют сайт в AI-ответах:
   - `Googlebot` (Google Search + AI Overviews + Gemini grounding)
   - `Bingbot` (Bing + Microsoft Copilot)
   - `OAI-SearchBot` (ChatGPT Search)
   - `ChatGPT-User` (fetch по запросу пользователя ChatGPT)
   - `Claude-SearchBot` (Claude web search)
   - `Claude-User`
   - `PerplexityBot`
   - `Perplexity-User`
3. Комментариями подписываем назначение каждой группы.
4. **Training-ботов (`GPTBot`, `ClaudeBot`, `Google-Extended`, `CCBot`, `Applebot-Extended`, `Meta-ExternalAgent`) НЕ блокируем** — этот вопрос стоит решать отдельно (потеря присутствия в обучающих датасетах ≠ потеря AI-цитирования, но политика по training-контенту — бизнес-решение). Оставляем TODO-комментарий в файле.
5. Оставляем директиву `Sitemap: https://tokenbel.info/sitemap.xml` в конце.

**Валидация:** файл читается по `/robots.txt`, проверяем через `curl` после деплоя.

### Блок 2. FAQPage + Article JSON-LD

#### 2a. FAQPage на `/faq/`

**Текущее состояние:** JSON-LD уже есть (`faq/index.html`, строки 145–193), но содержит только **5 вопросов**. На странице фактически больше блоков (категории «Основы», «Как купить», «Метрики»…).

**Что делаем:**
1. Проходим по всей странице `faq/index.html`, собираем все реальные Q/A пары (визуальные вопросы и ответы, которые видит пользователь).
2. Обновляем существующий `FAQPage` JSON-LD: расширяем `mainEntity` до полного списка, синхронизируем формулировки с видимым на странице текстом (Google требует, чтобы ответ в schema совпадал с ответом на странице).
3. Проверяем результат в Google Rich Results Test после деплоя.

#### 2b. Article JSON-LD в карточках «Последние новости» на главной

**Текущее состояние:** в `index.html` секция `#news` (строки 654–737) содержит 4 карточки-ссылки. JSON-LD отсутствует.

**Что делаем:**
1. Определяем, какие карточки — реально «новости с датой» (доллар — да, статистика за декабрь/ноябрь — да), какие — вечнозелёный гайд (YTM). Для новостей используем `NewsArticle`, для гайда — `TechArticle` или `Article`.
2. Добавляем **один общий** блок `<script type="application/ld+json">` в `<head>` `index.html` с массивом объектов (по одному на карточку). Схема каждого объекта:
   ```
   { "@type": "NewsArticle",
     "headline": "...",
     "datePublished": "2026-06-24",
     "url": "https://dashboard.tokenbel.info/events/...",
     "description": "...",
     "author": { "@type": "Organization", "name": "TokenBel" },
     "publisher": { "@type": "Organization", "name": "TokenBel",
                    "logo": { "@type": "ImageObject",
                              "url": "https://static.tokenbel.info/files/180x180.png" } },
     "mainEntityOfPage": "https://dashboard.tokenbel.info/events/..."
   }
   ```
3. Даты, заголовки и описания берём **1-в-1** из уже существующей вёрстки карточек (никакого нового текста).
4. Существующий блок с `WebSite` + `Organization` не трогаем.

**Валидация:** Rich Results Test для главной и FAQ.

### Блок 3. Виджет «Рынок сегодня» с реальными цифрами

**Цель:** дать краулерам и AI-моделям конкретные, уникальные, регулярно обновляемые данные, которые нельзя выдумать из training data.

**Место размещения:** новая секция на главной `index.html`, вставляется **сразу после Hero-блока** (после строки ~194, до текущей следующей секции). Название секции: «Рынок Беларуси сегодня».

**Источник данных:** есть API `https://hype.tokenbel.info/` (закреплено в памяти проекта). Нужно определиться до реализации, какой именно endpoint использовать — см. вопрос ниже.

#### 3a. Что показываем (6 метрик в 2 ряда по 3, адаптив: 1/2/3 колонки)

Примерный состав (финальный список зависит от того, что реально отдаёт Hype API):
1. **Активных эмиссий токенов** — число
2. **Общий объём эмиссий, BYN** — сумма
3. **Средневзвешенная доходность (YTM), % годовых** — по активным облигационным токенам
4. **Сделок за 24 часа** — число + объём
5. **Курс USD/BYN и RUB/BYN** — с изменением за день
6. **Обновлено:** timestamp последнего обновления

Каждая карточка: крупная цифра, подпись, дельта за сутки (если применимо), микроподпись «источник: биржи Finstore / Bynex / Fainex / Whitebird».

#### 3b. Как рендерим (два слоя — важно для SEO/AEO)

**SSR-слой (для краулеров и AI):** в HTML захардкожены **последние известные значения** (обновляются при каждом билде или вручную). Это критично — краулеры видят цифры сразу, без ожидания JS.

**Клиентский слой (для пользователей):** Alpine.js-компонент с `x-init` делает `fetch()` к Hype API и подменяет числа на актуальные. При ошибке — SSR-значения остаются.

Пример структуры одной карточки:
```
<article class="stat-card">
  <div class="text-3xl font-bold" x-text="data.emissions ?? '128'">128</div>
  <div class="text-sm text-gray-600">Активных эмиссий токенов</div>
  <div class="text-xs text-green-600" x-text="data.emissions_delta ?? '+3 за неделю'">+3 за неделю</div>
</article>
```

#### 3c. JSON-LD для виджета

Добавляем `Dataset` schema с описанием набора метрик и `dateModified` — это официально признанный schema.org тип, повышает шансы попадания в AI-ответы на запросы типа «сколько токенов в Беларуси».

#### 3d. Обновление alt-текстов и микрокопии

Пока делаем виджет — заодно правим существующую «micro-metrics row» под hero (строки 170–194 index.html): текущие «2 500+ компаний · 2 400+ акций» — статичные. Либо синхронизируем с виджетом, либо переносим ту же логику fetch.

### Открытые вопросы (нужны до реализации Блока 3)

1. **Endpoint Hype API для агрегированной статистики** — есть ли готовый (например, `/stats/overview`), или нужно собирать из нескольких? Если готового нет — реализуем виджет со статичными SSR-значениями без fetch (обновление вручную).
2. **CORS** — разрешает ли `hype.tokenbel.info` запросы с `tokenbel.info` из браузера? Если нет — только SSR-цифры, либо прокси через отдельный edge-эндпоинт (вне текущего плана).
3. **Финальный список метрик** — какие 4–6 показателей самые ценные для целевой аудитории? Мой список выше — черновик.
4. **Блок 1: блокировать ли training-ботов** (`GPTBot`, `ClaudeBot`, `Google-Extended`) — сейчас в плане не блокируем. Подтвердить.

Если по вопросам 1–3 нет данных сейчас — реализуем Блок 3 в статическом виде (обновляемые вручную цифры + `<meta>` с датой обновления), это уже даст 80% эффекта для AEO/GEO.
